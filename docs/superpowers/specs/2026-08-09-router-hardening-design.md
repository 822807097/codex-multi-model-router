# 本地多模型路由安全与协议强化设计

## 目标

在保持零依赖、仅监听回环地址和现有 Codex 使用方式的前提下，修复已确认的凭据误发、模型误路由、Chat SSE 数据损坏、HTTP 响应截断、跨任务状态串用和视觉中继资源失控问题。

## 设计边界

- 不实现完整对话数据库或通用 `previous_response_id` 历史缓存。
- 不改变原生 Responses 正常流的事件正文，只观察必要的完成状态。
- 不允许发送 SSE 响应头后切换到不同 wire API 的备用目标。
- 不新增 npm 依赖，不部署、不提交、不操作运行版本。

## 路由与认证

- 未匹配模型默认返回 `unknown_model`，仅显式配置的默认目标可以兜底。
- ChatGPT 登录态只由 `useOpenAiAuth: true` 启用，`name` 和 `platform` 不再隐式授权。
- chatgpt.com 专属请求体改写同样只由显式官方身份标志启用。
- 第三方目标只转发安全请求头白名单；额外头必须通过 target 配置显式允许。
- 同一模型的备用目标只能在相同 wire API 内自动 failover。

## Chat SSE 转换

- OpenAI-compatible Chat 默认按真实 delta 拼接；累计帧兼容必须显式配置，不能自动猜测。
- 工具调用同时维护 index、call ID 和帧位置别名，避免字段有无变化时拆分调用。
- 非 JSON data 帧、未知终止原因和内容过滤必须产生可判定失败或 incomplete。
- 单个 SSE 事件、累计正文和工具参数均有字节上限。
- 工具别名使用结构化来源键并在最终名称上循环查重。

## HTTP 传输

- 非默认端口进入 Host 请求头。
- chunked 结束时验证零块和完整结尾；Content-Length 响应验证实际字节数。
- 控制请求的 dechunk 解码拒绝非法或截断数据。
- 错误正文只读取片段时同时销毁对应上游 socket。

## 状态与上下文

- 不再通过全局唯一 call ID 跨任务恢复工具调用。
- 模型级供应商选择不再污染新的聊天任务。
- 检查点来源省略或截断工具输出中的高风险正文，并做常见凭据脱敏。
- 同一任务检查点使用版本号，较旧并发请求不能覆盖较新进度。
- Chat 合成 response ID 切到原生 Responses 时，只有请求已经携带足够完整输入才移除无效私有 ID；增量输入不足时返回明确错误。

## 资源边界

- 默认请求体上限下调，并增加并发请求数/全局缓冲字节预算。
- 视觉缓存使用 SHA-256 key，不保留 data URL 原文；同图请求 single-flight。
- 每请求图片数量和视觉调用并发数都有上限。

## 验证标准

- 每个已确认 Bug 先新增会失败的回归测试，再实现最小修复。
- `npm test`、各新增定向测试和 `node --check codex-router.mjs` 全部通过。
- 不进行真实供应商调用；live 测试只修正配置覆盖，不自动执行。
- `git status` 只包含本目标明确修改的源码、测试、配置和文档。
