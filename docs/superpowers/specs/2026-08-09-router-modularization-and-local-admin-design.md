# Codex 本地多模型路由持续优化路线图

日期：2026-08-09
状态：路线图已获原则批准，等待书面复核

## 1. 背景

当前路由已经具备官方 Responses、第三方 Chat 转换、跨供应商候选、视觉中继、上下文预算、目标检查点和 SSE 保活等能力，但入口文件仍同时承担配置解析、目录读写、认证刷新、视觉编排、响应管线和 HTTP 请求生命周期。Chat 与原生 Responses 也各自实现了 SSE 分帧逻辑。后续继续增加持久化和管理界面时，如果不先稳定模块边界，入口复杂度和回归风险会继续上升。

本阶段采用“先纯逻辑、后副作用；先后端边界、后管理界面”的顺序，逐步把 `codex-router.mjs` 收敛为组合入口。每个阶段必须在完整离线回归通过后才能进入下一阶段。

本文是五阶段路线图，不作为一次性大改的实施规格。每个阶段都要另写独立设计和实施计划；本轮书面复核通过后只进入阶段一“配置预检”，其余阶段在前一阶段全绿后分别细化和复核。

### 1.1 外部项目参考边界

选择性参考 [Wei-Shaw/sub2api](https://github.com/Wei-Shaw/sub2api) 的成熟网关模式：handler/service/gateway 职责分层、显式 failover 状态、心跳字节与语义响应提交分离、集中配置校验、管理端信息架构和 simple-mode 功能裁剪。

sub2api 面向多用户计费网关，使用 Go、Gin/Viper、Vue/Vite、PostgreSQL、Redis 和 Docker，与本地零依赖工具的部署目标不同。本项目不引入这些框架，也不吸收账号、计费、配额、CAPTCHA、分布式调度、数据库运维或公网安全体系。sub2api 采用 LGPL-3.0-or-later；这里只借鉴公开设计思想，不复制或改写其源码实现，保持本项目自身许可证边界。

## 2. 目标

1. 启动监听前聚合检查配置错误，避免非法配置被静默忽略。
2. 按明确职责继续拆分主入口，保持依赖单向、接口可独立测试。
3. 抽取 Chat 与 Responses 共用的 SSE 分帧层，不混合协议语义。
4. 为长任务检查点增加默认关闭的冷重启持久化。
5. 增加严格零依赖的轻量本地 Web 管理页。
6. 保持当前合法配置、模型选择、同任务切换模型、直连/代理、视觉中继和工具调用行为兼容。

## 3. 非目标与硬边界

- 不引入 npm 包、前端框架、Node Web 框架、数据库或外部服务。
- 不增加 Web 登录、浏览器白名单、Host/Origin 门禁、CORS 限制或公网部署能力；管理 API 明确信任本机浏览器环境，这是用户确认的本地单机取舍。
- 服务仍只监听 `127.0.0.1`。
- 不实现 Anthropic Messages、完整 `previous_response_id` 会话缓存或新的供应商 failover 语义。
- 不在管理页内启动、停止、重启或杀死路由进程。
- 不让配置保存自动热切换当前进程；保存后明确提示需要人工重启。
- 不把 API Key、OAuth Token、认证头值或完整请求正文写入持久化检查点。
- 实施和测试期间不访问或写入 `A:\CodexData\router`，不运行启动、停止、重启脚本，不做真实供应商网络测试。
- 不执行 `git commit`、`git push` 或部署。

## 4. 总体架构

最终的 `codex-router.mjs` 只负责以下组合工作：

1. 解析进程路径和环境覆盖。
2. 加载并预检配置。
3. 构造配置、目录、认证、视觉、检查点、响应管线和请求处理器实例。
4. 创建 HTTP 服务并监听回环地址。
5. 处理进程级致命异常和优雅退出。

业务模块不得隐式读取全局 `cfg`。除专门的文件适配器外，模块不得自行读取 `process.env` 或任意文件路径；入口通过依赖注入传入运行参数、文件操作、时钟、日志和网络请求函数。这样既保留零依赖，也能用 Node 内置测试运行器覆盖异常路径。

建议的最终边界如下：

| 模块 | 单一职责 |
| --- | --- |
| `lib/router-config.mjs` | 配置预检、环境覆盖解析、运行参数生成、target 正则编译 |
| `lib/model-catalog.mjs` | 模型目录读取、上下文字段更新、`/models` 列表构造和原子写回 |
| `lib/vision-relay.mjs` | 图片识别请求、非文本 part 遍历和降级策略编排 |
| `lib/openai-auth.mjs` | ChatGPT 登录态读取、JWT 过期判断、single-flight 刷新和原子写回 |
| `lib/response-pipeline.mjs` | Responses SSE 响应头、心跳、错误结束和两类上游响应管线 |
| `lib/chat-request.mjs` | Responses→Chat 请求装配、上下文预算和检查点生成编排 |
| `lib/router-handler.mjs` | HTTP 端点、请求体预算、候选循环、状态域和 failover 编排 |
| `lib/sse-decoder.mjs` | 无业务语义的增量 SSE 分帧 |
| `lib/checkpoint-persistence.mjs` | 检查点快照加载、校验、原子保存和单写者协调 |
| `lib/admin-api.mjs` | 管理状态、配置读取、预检、保存和检查点管理 API |
| `web/*` | 原生 Web Components 管理界面与纯前端状态函数 |

模块拆分按依赖由外向内推进，不按行数机械拆分，也不建立笼统的 `utils.mjs`。

## 5. 阶段一：配置预检

### 5.1 接口

`lib/router-config.mjs` 提供：

```js
inspectRouterConfig(rawConfig, context)
prepareRouterConfig(rawConfig, context)
formatConfigIssues(issues)
```

`inspectRouterConfig` 返回 `{ errors, warnings }`。每条问题固定为：

```js
{ severity, code, path, message }
```

`prepareRouterConfig` 在存在错误时抛出带完整 `issues` 的 `RouterConfigError`；成功时返回 `{ config, runtime, targets, warnings }`。`runtime` 保存端口、代理、路径、心跳和请求预算等有效值，`targets` 保存按原顺序编译后的正则。第一阶段不重命名现有字段，也不改变合法配置的默认值语义。

### 5.2 启动错误

以下问题必须在 `server.listen` 之前一次性报告并退出：

- 根配置不是对象，或 `targets` 缺失、为空、没有有效目标。
- 监听端口、代理端口或 target 端口不是 `1..65535` 的整数。
- target 缺少 `name`、`match`、`host`，正则非法，协议不是 `http/https`，解析后的 wire API 不是 `responses/chat`。
- 非空 prefix/endpoint 路径不是以 `/` 开头，或 host、路径、header 名值含 CR/LF；空 prefix 继续视为合法。
- 非官方 target 缺少合法 `envKey`；官方登录态与第三方认证配置互相冲突。
- 超时、心跳、请求体、缓冲、并发、历史、视觉和检查点容量不是有限正数，或跨字段预算互相矛盾。
- 模型能力正则非法、上下文窗口无效、安全比例不在 `(0, 1]`，输出和预留明显超过上下文窗口。
- `modelContext` 启用时压缩阈值超过上下文窗口，或 slugs 不是字符串数组。

本阶段会改变所有上述非法配置的失败时机：非法正则不再被跳过，无效正数不再回退默认值，未知 wire API/协议/路径和跨字段矛盾不再延迟到首个请求或底层系统调用才失败。合法配置、环境覆盖优先级和默认值保持不变；README 必须完整列出这些非法配置兼容性变化。

### 5.3 启动警告

以下情况只警告，不阻止未使用的模型通道之外的路由工作：

- target 或视觉中继引用的环境变量当前未设置；只显示变量名，不读取到诊断文本。
- target 名称重复、目标完全重复，或相同 match 文本/随仓已知模型样本命中的候选混用 wire API；不尝试静态证明任意正则是否相交。
- `protocol:http` 同时配置 `viaProxy:true`，或显式状态域跨不同端点复用。
- auth/catalog 使用相对路径，或转发头包含路由不会透传的 hop-by-hop 字段。

未知供应商扩展字段必须保留，避免限制国内兼容网关。

## 6. 阶段二：主入口模块拆分

拆分顺序固定为模型目录、视觉中继、响应管线、OpenAI 登录态、Chat 请求装配、主请求处理器。每次只迁移一个职责，并先补行为刻画测试。

### 6.1 模型目录

目录纯函数接收目录对象和 `modelContext`，返回新对象和 `changed` 标记；文件适配层负责限量读取、JSON 解析、同目录临时文件、同步落盘和原子替换。`/models` 列表构造也在该模块完成，并继续只声明 `{ streaming: true }`。

### 6.2 视觉中继

视觉模块接收缓存、并发限制器、密钥读取函数、网络请求函数和日志函数。它不访问全局配置。相同图片 single-flight、全进程并发限制、每请求图片上限和失败降级行为保持不变。

### 6.3 响应管线

Responses 头、心跳、错误事件、原生 Responses 旁路观察和 Chat 转换管线集中到同一模块。管线显式区分 `headersCommitted`、`heartbeatBytes` 和 `semanticStarted`：SSE 注释心跳不算模型语义响应，不能单独阻止同 wire API 候选 failover；首个模型事件写入前原子停止心跳并把 `semanticStarted` 置为 true，之后禁止重放或切换候选。客户端关闭必须统一停止心跳、销毁上游流和 socket；响应头发送后只能以 SSE 结束。

### 6.4 登录态与请求装配

OpenAI 登录态模块保持临期刷新、single-flight 和桌面端并发更新保护。Chat 请求模块保持工具转换、上下文预算、检查点生成、降级和最终预算复核。二者通过注入的文件和网络函数测试，不直接创建服务器。

### 6.5 主处理器

`createRouterHandler(dependencies)` 返回 HTTP handler。它只编排请求预算、模型候选、状态域、每候选认证、failover 和响应管线，不包含协议转换细节。该接口预留可选的管理 handler；阶段五注入后优先匹配管理 API，未命中时再进入模型路由。

## 7. 阶段三：SSE 分帧复用

`lib/sse-decoder.mjs` 只解决传输分帧，不理解 Chat delta、工具调用或 Responses 生命周期。

### 7.1 行为

- 使用严格 UTF-8 增量解码，支持多字节字符跨 chunk。
- 支持 LF、CRLF、CR 及分隔符跨 chunk。
- 支持注释、未知字段、多行 `data` 和无尾空行的最后事件。
- 按原始字节计算单事件上限：计入事件内的字段、注释和行结束符，不计终止该事件的空行分隔符；边界值必须稳定。
- 输出规范化 `{ event, data }`；业务层自行处理 JSON 和 `[DONE]`。
- Responses observer 继续原样转发输入 Buffer，不允许公共解析器重编码上游字节。

### 7.2 语义边界

Chat 转换器继续独占 choice/delta、reasoning、并行 tool_calls 重组、Responses 生命周期生成和 `response.failed` 收口。Responses observer 继续独占终态类型、status、一致性和单终态校验。两者不得合并成一个通用 Transform。

严格 UTF-8 和裸 CR 支持会收紧或扩展 Chat 的现有边界行为，实施前必须用刻画测试锁定预期。

## 8. 阶段四：检查点可选持久化

### 8.1 范围

持久化默认关闭，只承诺同一机器上的冷重启恢复，不承诺多进程实时共享。启用时必须显式配置文件路径，避免路由在未知目录创建状态文件。

每份快照绑定运行身份 namespace。namespace 由显式 `stateGeneration` 和排序后的目标认证域生成：官方通道使用账号 ID 的 SHA-256，API 通道使用环境变量名与当前密钥的域分离 SHA-256，静态认证 header 只参与哈希而不落原值。任一 ChatGPT 账号、API Key、租户身份或 `stateGeneration` 变化都使旧快照只读归档并从空 store 启动，保持“身份切换后重启清状态”的现有边界。

快照只保存：

- 已规范化的九栏目检查点。
- task、exact、response 的域分离 SHA-256 索引。
- 条目更新时间、过期时间和 LRU 恢复所需顺序。
- response id 碰撞后的歧义哨兵。

快照不保存：

- 原始 task、response、session 或 prompt cache ID。
- 用于生成摘要的历史来源、请求体、工具结果全文。
- API Key、Token、Cookie、认证头和环境变量值。
- 进程内 `latestRequests` 与 request sequence；重启后重新建立并发顺序。

### 8.2 文件协议

- 使用带版本号和校验字段的有界 JSON 快照；本地单机第一版不强制加密。
- 文档明确提示快照包含任务摘要，默认关闭且由用户选择路径。
- 加载前限制文件字节，随后校验版本、结构、哈希格式、TTL 和条目上限。
- 不信任冗余索引，必须从已验证条目重建 Map、所有者和歧义状态。
- 保存采用串行 debounce、同目录临时文件、文件同步和原子替换；最后良好快照保留为备份。
- 写失败只使持久化降级为内存模式，不中断当前模型请求，并对重复错误限频记录。
- POSIX 创建快照、临时文件和锁时使用仅当前用户可读写的权限；Windows 使用当前用户目录和系统 ACL 的最佳努力，不承诺跨平台权限模型等价。

### 8.3 重叠进程

持久化文件旁使用原子创建的锁目录，目录内记录随机 owner ID、PID、创建时间和定期刷新的 heartbeat。写入前必须再次核对 owner ID 和当前快照 revision；丢失所有权或 revision 变化时放弃替换并退回只读模式。超过配置的陈旧阈值后，竞争者用原子 rename 隔离旧锁目录，再创建新锁；原 owner 后续因 owner/revision 检查失败而不能覆盖新快照。

第二进程可以加载快照但先以只读模式运行，并定时尝试获取锁；获取后重新加载最新快照，再按条目更新时间合并本进程内更新。无法可靠合并的同任务冲突保留较新的检查点，response 歧义哨兵取并集。优雅退出先停止新 debounce、串行 flush、核对 owner、关闭文件句柄，再删除自己持有的锁目录。崩溃遗留锁由 heartbeat 规则恢复。只读实例的检查点删除 API 返回 `409`，不得修改内存或磁盘。第一版不宣称无缝的跨进程一致性。

## 9. 阶段五：轻量本地 Web 管理页

### 9.1 技术选择

后端继续使用 `node:http`。前端使用原生 ES Modules、Web Components、`<template>`、Fetch API 和 CSS Variables，不引入 Express、Fastify、React、Vue、Preact、Vite、HTMX、Alpine 或 CDN 资源。

界面通过 `http://127.0.0.1:<port>/admin` 访问，静态文件放在 `web/`。管理 API 使用 `/_admin/api/*` 命名空间，并与模型转发路径隔离。

### 9.2 第一版功能

- 总览：运行端口、配置路径、启动时间、目标数量、警告数量和持久化模式。
- 模型通道：target 名称、匹配规则、协议类型、上游模型、直连/代理和环境变量是否已设置。
- 配置编辑：顶层限制、代理、超时、模型能力、视觉中继、检查点和 targets 的结构化表单。
- 配置预检：保存前调用与启动相同的 `router-config.mjs`，按 path 显示全部错误和警告。
- 原子保存：保留格式化 JSON 和一份最后良好备份，返回 `restartRequired: true`。
- 检查点状态：只显示数量、字节、最早/最晚过期时间和读写模式；清空操作要求二次确认。

第一版不提供实时请求正文、API Key 输入、OAuth Token 展示、任意文件浏览、终端、进程控制、自动重启、在线模型市场或复杂图表。

### 9.3 管理 API

建议端点：

| 方法与路径 | 行为 |
| --- | --- |
| `GET /admin`、`GET /admin/*` | 只返回构建时固定清单中的静态资源，不做任意路径拼接 |
| `GET /_admin/api/status` | 返回脱敏运行状态、targets 和环境变量存在性 |
| `GET /_admin/api/config` | 返回可编辑配置；敏感静态 header 值只返回占位状态 |
| `POST /_admin/api/config/validate` | 只预检，不写文件 |
| `PUT /_admin/api/config` | 预检成功后原子保存，当前进程不热加载 |
| `GET /_admin/api/checkpoints` | 返回统计和一次性清空确认值，不返回检查点正文 |
| `DELETE /_admin/api/checkpoints` | 校验一次性确认值且当前实例持有写锁后执行可恢复清空 |

API 请求体使用独立的小型字节上限。配置保存必须带读取时返回的 revision；revision 不匹配返回冲突，避免两个标签页静默覆盖。revision 由读取时磁盘原始文件字节的 SHA-256 生成，不依赖文件时间戳或 JSON 格式化结果。

敏感静态 header 值不进入浏览器。每次读取配置时，后端为当前 revision 和敏感 path 生成随机、进程内保存的不可伪造占位 token，浏览器只收到 `{ $preserveSecret: token }`。PUT 只有在 revision、path 和 token 都精确匹配时才从当前磁盘回填原值；未知 token 或把占位对象写入其他 path 必须拒绝。显式删除使用独立的 `secretDeletes` path 列表和确认值，不能通过删掉占位对象隐式完成。第一版管理页不能新增或修改敏感 header 值，用户仍通过环境变量或手工编辑配置完成这类操作。

### 9.4 前端结构

页面按总览、模型通道、路由配置、长任务和诊断五个区域组织。组件只负责显示和用户交互，配置序列化、revision、错误 path 映射和脏状态判断拆成可在 Node 中测试的纯函数。前端从完整原始配置副本修改已知 path，不按表单字段重新构造对象，确保未知供应商字段、数组顺序和 `_comment` 原样保留。前端校验只用于即时提示，后端预检始终是最终判定来源。

检查点清空需要 GET 返回的一次性确认值，且只允许当前持有持久化写锁的实例执行。后端先把现有快照移动为带时间戳的可恢复备份，再清空内存并落盘空状态；API 返回备份路径和恢复提示。只读实例或确认值不匹配返回 `409`。

## 10. 数据流与错误处理

### 10.1 正常模型请求

请求处理器先匹配管理和健康端点，再为模型请求申请请求预算、解析模型、选择候选、验证状态域、按候选构造认证和请求体，最后交给 Chat 或 Responses 响应管线。任何 SSE 头发出前的错误返回 JSON；发出后只发送规范化 SSE 错误并结束。

### 10.2 配置保存

管理页读取配置和 revision，用户修改后先调用预检。保存端点重新读取磁盘、校验 revision、重新执行完整预检，再写入临时文件、同步并原子替换。成功只更新磁盘文件，返回需要重启；当前进程的 targets、认证和预算保持不变。

### 10.3 持久化故障

损坏、超限、未知版本或校验失败的快照不进入内存；加载器尝试最后良好备份，仍失败则使用空 store。错误密钥不是第一版问题，因为第一版不加密。任何快照错误不得使主路由停止服务。

### 10.4 客户端断开

请求独占的视觉遍历、检查点生成和上游 socket 共享请求级 AbortSignal。认证刷新和图片 single-flight 等共享操作使用独立所有权：客户端关闭只取消自己的等待，只有最后一个等待者退出时才能取消共享任务。所有心跳、锁重试和 debounce 定时器必须可清理并 `unref`。

## 11. 测试策略

所有阶段遵循 TDD：先加入会失败的最小测试，再写实现，最后重构。不得用真实供应商接口作为通过条件。

### 11.1 配置

- 表驱动覆盖每个稳定 error code/path、多错误聚合和警告分类。
- 随仓 `config.json` 在显式环境变量集合下零错误。
- 诊断文本不得包含测试密钥、Token 或敏感 header 值。
- 环境覆盖优先级、target 顺序、正则和 provider alias 与当前行为一致。
- 非法配置子进程必须在绑定端口前退出。
- 兼容夹具覆盖所有原先会被默认、跳过或延迟失败的非法值，证明新的稳定 error code 和启动失败时机。

### 11.2 模块拆分

- 每次迁移前后复用同一输入输出夹具。
- 文件和网络副作用通过注入的适配器验证调用顺序、原子写和 abort。
- 主入口集成测试继续使用临时目录、临时端口和 `/_admin/shutdown` 优雅关闭。

### 11.3 SSE

- 分隔符和 UTF-8 跨 chunk、LF/CRLF/CR、多行 data、注释、未知字段和无尾空行。
- 单事件限制的等于边界与超一字节。
- Chat 文本、推理、并行工具调用、累计工具片段和失败生命周期完整回归。
- Responses 输入与输出 Buffer 字节完全一致，终态约束保持不变。

### 11.4 检查点持久化

- 快照 round-trip、过期淘汰、容量上限、碰撞哨兵和索引重建。
- 截断、未知版本、非法哈希、超限文件和备份回退。
- temp、同步、rename 和磁盘错误后旧快照仍可读取。
- 身份 namespace 变化时旧快照不得载入，原文件必须保留为可诊断归档。
- Windows 与 POSIX 分别覆盖锁目录创建、owner 校验、heartbeat、陈旧锁隔离、崩溃恢复、只读降级、获取锁后的重新加载与冲突合并。
- 优雅退出 flush 不丢已排队更新；失去锁的旧 owner 不能覆盖新 revision；只读实例不能执行清空。
- 快照不得出现原始 task/response ID、已知密钥或认证 marker。

### 11.5 管理 UI

- Node 内置测试覆盖所有管理 API、请求体上限、revision 冲突、不可伪造敏感字段占位、显式删除、一次性清空确认和原子保存。
- 前端纯函数覆盖配置序列化、脏状态、错误 path 映射和表单增删；读取→修改已知字段→保存必须保留未知供应商扩展字段、数组顺序和 `_comment`。
- 使用真实浏览器做离线烟雾测试：页面加载、编辑、预检、冲突提示和保存提示；测试实例使用临时端口并通过管理端点优雅关闭。
- 键盘操作、窄屏布局、中文错误可读性和浏览器控制台无错误纳入人工/浏览器验收。
- README 使用最终管理页截图说明入口、配置预检和“保存后需人工重启”状态。

### 11.6 每阶段固定门禁

- 本阶段定向测试通过。
- `node --test "test/*.test.mjs"` 全量通过。
- 所有 `.mjs` 执行 `node --check`。
- `node --check A:\codex-multi-model-router\codex-router.mjs` 通过。
- JSON、脚本静态解析、零外部依赖和 `git diff --check` 通过。
- 不启动运行版本、不访问运行目录、不部署、不提交。

## 12. 文档与兼容性

`README.md` 和 `config.json` 中文注释必须随对应阶段同步更新。配置预检完整记录非法配置由默认/忽略/延迟失败改为启动前聚合失败；持久化说明默认关闭、文件内容、身份切换和冷重启边界；UI 说明本地地址、明确的本机信任假设、功能范围、保存后需人工重启以及不管理 Key。

现有配置字段保持兼容。新增配置全部有关闭或安全默认值。管理页必须通过同一预检模块写出可被命令行启动路径接受的配置，不能形成第二套配置语义。

## 13. 实施顺序与完成定义

实施严格按以下顺序推进：

1. 配置预检。
2. 主入口模块拆分。
3. SSE 分帧复用。
4. 检查点可选持久化。
5. 轻量本地 Web UI。
6. README、配置示例和最终交付审计。

完整目标只有在五个阶段全部实现、文档同步、全量离线验证和需求逐项审计完成后才能标记完成。任何单阶段通过都只代表阶段进度，不代表持续目标完成。
